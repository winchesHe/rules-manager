# Agent Dashboard UX 动效与筛选反馈

## 目标

在不改变现有信息架构、配色和页面布局的前提下，补齐页面硬切、筛选瞬时替换和按钮缺少按压反馈的问题，
让现有功能的状态变化更容易被感知。

## 交互规范

- 主导航与 Rules 分区切换使用原生 CSS 180ms 淡入和 6px 纵向位移，避免为微动效增加运行时依赖。
- Scan 的最近结果 / 新建扫描 / 历史记录、Projects 的列表 / 详情使用同一页面过渡。
- Scan 结果筛选、Projects 搜索与筛选、项目 Session 搜索与筛选使用 140ms 结果过渡。
- 文本搜索使用 `useDeferredValue`。新条件计算期间保留旧结果并降低透明度，完成后再切换，避免输入阻塞和白屏。
- Projects 列表显示「当前结果 / 总数」，以 `aria-live` 向辅助技术播报；过渡容器使用 `aria-busy` 标记处理中状态。
- 主导航进入 Scan / Projects 时立即呈现页面结构，不显示居中的全屏加载转圈；数据返回前使用与实际表格
  列数、行高一致的 HeroUI shimmer 骨架，避免空白页、错误空状态和布局跳动。
- 可点击按钮提供 1px 下沉与 0.99 缩放的按压反馈。
- `prefers-reduced-motion: reduce` 下页面、筛选和按钮位移动画全部归零。

## 验收方式

| 观察点 | 验证方式 |
|---|---|
| 主导航和内部页面切换不再硬切，且不改变原布局尺寸 | UX 合同测试 + Electron 视觉检查 |
| 切换到 Scan / Projects 显示表格骨架，不出现居中的全屏 Loading | UX 合同测试 + Electron 快速切页检查 |
| 快速输入搜索词时输入保持响应，结果更新有忙碌反馈 | 合同测试 + Electron 交互检查 |
| 筛选结果数量正确，空状态仍保留 | 既有 view-model 测试 + App 全量测试 |
| reduced motion 不产生位移和时长 | UX 合同测试 |
| Chat 固定高度、侧栏与窗口按钮不回归 | 既有布局 / 拖拽测试 + production build |
