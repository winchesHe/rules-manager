# 候选规则多选与批量操作

## 范围与验收标准

- 候选规则表格支持逐行多选与当前可见列表全选。
- 已选工具栏显示数量，并提供批量接受、批量拒绝与清空选择。
- 切换状态或生成批次时清空选择，避免操作不可见候选。
- 批量状态更新在一个 DB 事务中完成；任一 ID 不存在时整批回滚。
- 单条审核和发布流程保持不变。

## Step 1：Core 批量事务

- 单一改动：新增批量状态更新方法与 IPC。
- 观察点：多个候选一次更新；包含不存在 ID 时已有候选保持原状态。
- 验证方式：Core rule candidate review 单测与 App IPC 契约测试。

## Step 2：候选列表选择

- 单一改动：增加表头/逐行 Checkbox 和局部选择状态。
- 观察点：表头支持全选与半选，切换状态/批次后选择清空。
- 验证方式：App 视图契约与 production build；HeroUI Table 内的 Checkbox 必须显式使用
  `slot="selection"`，且 HeroUI v3 复合组件必须包含 `Content / Control / Indicator` 才会
  绘制可见控件；在真实 Electron 页面验证无运行时白屏、控件可见并能唤起批量工具栏。

## Step 3：批量操作工具栏

- 单一改动：接入批量接受/拒绝，提交期间禁用控件，成功后刷新列表与数量。
- 观察点：草稿页显示两个动作；已接受/已拒绝页只显示有意义的反向动作。
- 验证方式：App 全量测试及真实构建。

## Step 4：回归与记录

- 单一改动：同步设计与过程记录。
- 观察点：发布仍只读取已接受的全局规则。
- 验证方式：Core/App 全量测试、build、`git diff --check`。
