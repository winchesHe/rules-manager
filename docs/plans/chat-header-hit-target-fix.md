# Chat 顶部按钮热区修复

## 问题与范围

- 窗口顶部拖拽层以 `z-index: 1000` 覆盖 Chat Header，导致历史按钮和对话管理按钮的可见区域被拦截。
- 保留现有历史切换和对话管理能力，不调整对话数据、生命周期或窗口拖拽层的全局范围。
- 将图标按钮的可访问名称放到实际交互元素，并固定 32×32px 命中区。

## 观察点与验证方式

1. 结构测试：Chat Header 的交互层级高于窗口拖拽层，两个按钮具备显式命中尺寸和可访问名称。
2. 自动化回归：运行 App 测试，确认 Header、历史面板和管理弹窗契约保持完整。
3. 真实 Electron：分别点击历史按钮与 `…` 的可见中心，确认历史面板切换、管理弹窗打开且包含重命名和归档操作。
4. 完整验证：App/Core 全量测试、production build 与 `git diff --check` 通过。

## 验收标准

- 历史按钮完整可点，点击后可靠打开或关闭历史面板。
- `…` 点击后打开对话管理弹窗，不再表现为无响应。
- 顶部按钮保持 32×32px 点击区域，图标不承担按钮的可访问名称。
- 其他页面窗口拖动与 Chat 内容布局不回归。
