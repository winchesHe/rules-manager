# Agent Memory 文件定位入口

## 目标

在 Agent Memory 详情页提供明确的文件定位入口，使用户可以从只读预览直接在系统文件管理器中定位当前
`MEMORY.md`，无需手动复制路径。

## 范围与安全边界

- 入口放在详情页标题右侧，使用现有次级操作样式，不改变 Memory 的只读语义。
- Renderer 只提交 `agent + memoryId`；主进程从已发现的 Memory 来源重新解析路径，不接受 Renderer
  传入任意文件路径。
- 仅调用 Electron `shell.showItemInFolder`，不创建、修改或删除 Memory 文件。

## 执行与观察点

| 步骤 | 改动 | 观察点 | 验证方式 | 状态 |
|---|---|---|---|---|
| 1 | 主进程文件定位 IPC | 非法 Agent、空 id 和不存在/未生成来源均被拒绝 | IPC 布局契约测试 | 已完成 |
| 2 | 详情页入口与反馈 | 标题右侧显示入口，失败时展示明确错误 | Renderer 布局与 i18n 契约测试 | 已完成 |
| 3 | 完整验收 | 不改变只读预览、重新加载与返回行为 | App 测试、build、截图、`git diff --check` | 已完成 |

## 验收标准

1. Codex 与 Claude Memory 详情页标题右侧均显示“在文件夹中显示”。
2. 点击后由系统文件管理器定位当前 Memory 文件，而不是打开或编辑文件内容。
3. Renderer 无法借该 IPC 定位未被 Agent Memory 发现流程授权的任意路径。
4. 定位失败时页面显示错误，既有只读预览、重新加载和返回入口保持可用。
