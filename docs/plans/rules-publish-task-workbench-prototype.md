# 已接受规则发布台 HTML 原型

## 范围

- 新增一份可直接打开的独立 HTML 原型，不修改 Electron Renderer、Core、IPC 或本机发布目标。
- 原型采用 `task + wide` 页面结构，验证按「项目规则 / 全局规则」切换的单任务发布台。
- 项目规则模式保留规则勾选、Agent 全局指令文件多选、Claude/Codex Memory 目标切换、显式目标选择和
  独立的全部规则导出入口。
- 全局规则模式按当前真实数量展示紧凑空状态，不在没有规则时渲染完整 Agent 目标配置。

## 验收标准

- 默认进入第一个非空范围，当前样例直接打开「项目规则 1」。
- 顶部以“项目规则 / 全局规则 / Memory”三个同级入口切换任务；Memory 内 Claude 与 Codex 同一时间只展示
  一套目标配置，页面始终只有一个 Primary Action。
- Agent 全局规则模式支持显式多选 Claude、Codex、Copilot、OpenCode、Pi，并展示各自的全局指令文件路径。
- 勾选规则、切换目标类型和选择目标会同步更新底部摘要、按钮文案与禁用状态。
- 导出按钮仅模拟「导出全部已接受规则」，不受勾选项影响，也不写入磁盘目标。
- 发布、导出只产生原型内的成功反馈，不调用 Memory Manager API。
- 桌面和窄屏均无页面级横向溢出；Light/Dark 两种主题层级可读，键盘焦点可见。

## 观察点与验证方式

1. **信息架构**：规则范围先于目标配置，用户不再跨左右栏推断全局规则与项目目标的对应关系。
   - 验证：切换两个范围，确认每个范围只展示相关规则和操作。
2. **单一主操作**：先切换 Agent 全局规则或项目 Memory；Memory 内再切换 Claude/Codex，只有当前发布
   上下文对应的一个按钮可见。
   - 验证：切换发布方式、Agent 多选、Memory 目标、清空选择和重新选择，观察 Footer 摘要与按钮状态。
3. **语义边界**：项目导出明确作用于全部已接受规则，Memory 发布明确作用于勾选规则。
   - 验证：取消规则勾选后导出仍可用，Memory 发布禁用。
4. **静态质量**：原型无远程依赖，使用语义元素和原生表单控件。
   - 验证：HTML 解析、定向文本检查、浏览器交互和 `git diff --check`。
5. **响应式与主题**：宽屏使用规则区加 22rem 配置栏，窄屏转为自然单列。
   - 验证：桌面、窄屏及 Dark 模式分别截图检查。

## 验证结果

- 静态契约通过：文档语言、唯一 `id`、零远程资源、单一 Primary Action、原型安全说明、响应式和
  `prefers-reduced-motion` 均符合预期。
- 浏览器交互通过：Claude/Codex 目标切换、规则勾选、按钮禁用状态、动态路径、全局规则空状态、模拟发布
  与独立导出反馈均正常。
- 用户反馈后将 Memory 提升为顶部第三个同级入口：项目规则进入 Agent 全局指令文件发布，Memory 进入
  Claude/Codex 项目 Memory 发布；移除右栏重复的发布方式切换。
- 用户澄清主要问题是纵向留白，因此撤回主内容、目标栏、tab 宽度和 Agent 双列的横向扩展；保留并加强
  页头、卡片、表单、规则行和操作栏的纵向压缩，信息结构和横向比例恢复原设计。
- 返回入口在桌面端并入标题行右侧；未选择 Memory 目标时不再展示空路径占位，选择后才展开路径详情。
  2048×1024 下 Memory 卡片高度由约 455px 降至 382px，卡片底部整体上移约 112px。
- 用户进一步指出问题是主卡片下方未被工作区占用的整块页面背景。桌面端主卡片改为填满剩余视口高度，
  task grid 弹性扩展并将操作栏推至卡片底部；620px 以下恢复内容自然高度。
- 2048×1024 实测文档高度与视口均为 1024px，工作台底部约在 965px，无额外纵向滚动；390px 下
  `min-height` 回退为 0。
- 1440×900 与 390×844 视口均无页面级横向溢出；Light/Dark 主题可读，浏览器控制台无 warning/error。
- 本轮为独立文档原型，未修改 Renderer/Core/IPC，使用静态契约和浏览器视觉验收替代 App 自动化测试。
