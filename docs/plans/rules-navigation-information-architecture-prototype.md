# Rules 导航信息架构 HTML 原型

## 范围

- 新增一个独立 HTML 原型，验证 Rules 二级导航的信息架构与视觉分组。
- 保留主导航 `扫描 / 项目 / Chat / 规则`，不修改真实 Renderer、路由、IPC 或数据读取。
- Rules 二级导航改为两个轻量分组：
  - `规则管理`：`概览 / 规则工作台`
  - `Agent 上下文`：`Agent 指令 / Agent Memory`
- `生成的规则` 改名为 `规则工作台`，表达生成、审核、接受和发布的完整任务范围。
- 四个 Rules 入口提供可点击的内容示意，以便同时验证名称和页面职责是否匹配。

## 观察点

1. 用户能否从侧栏直接看出“规则处理”和“Agent 侧已有上下文”是两组不同对象。
2. `规则工作台` 是否比 `生成的规则` 更准确地覆盖生成、审核与发布。
3. `Agent 指令 / Agent Memory` 是否在保留独立入口的同时呈现为同一组。
4. Active、hover、pressed、focus 状态是否与现有 dark 主题一致，且不依赖额外字体或图标库。
5. 桌面和窄屏是否都不产生页面级横向溢出。

## 验证方式

- 静态合同：检查四个 `data-rules-view` 导航目标和四个对应内容视图唯一存在。
- JavaScript 语法：提取内联脚本并使用 Node 执行语法检查。
- 浏览器交互：逐一点击四个入口，确认 active 状态、`aria-current`、标题和内容同步切换。
- 响应式视觉：桌面视口与 390px 窄视口截图；检查页面 `scrollWidth <= innerWidth`。
- `git diff --check`：确认新增文件与过程记录无空白错误。

## 不在本轮

- 不修改真实 App 侧栏、`RulesSection` 或翻译文件。
- 不连接真实规则、Agent 指令或 Memory 数据。
- 不决定最终产品文案；本原型只用于信息架构评审。
